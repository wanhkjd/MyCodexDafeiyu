# Codex-dafeiyu 🐟

一个面向 **Windows x64** 的桌面陪伴小伙伴：可以聊天、互动、记录提醒，也可以陪你工作。

当前发布版本：**v1.7.0**（2026-11-02）。内置 **大肥鱼** 和 **白龙** 两种形象，切换形象不会更换人格，聊天记录、心情与养成状态共享。

**直接使用：[下载 v1.7.0 Windows x64 完整便携版](https://github.com/wanhkjd/MyCodexDafeiyu/releases/download/v1.7.0/Codex-dafeiyu-v1.7.0-windows-x64.zip)** · [发布说明与校验文件](https://github.com/wanhkjd/MyCodexDafeiyu/releases/tag/v1.7.0)

下载完整 ZIP → 全部解压 → 双击 `Codex-dafeiyu.exe`，无需安装 Node.js、npm 或 Git。

> GitHub 的 Code 页面、git clone 和「Source code」ZIP 提供的是源码；可双击启动的完整运行包在 **Releases 的 Assets（附件）** 中。两者用途不同。保留 Codex 联动，并支持 DeepSeek Harness 工作状态联动；聊天可以跟随本机 Codex / CC Switch 配置，也可以单独使用第三方 API。

## 功能介绍

### 小窗口控制面板

- 默认约 **900 × 680**，保留系统窗口边框；支持缩放窗口，不再把全部配置堆在一个长页面。
- 左侧 7 个分类，右侧 19 个页签：桌宠、心情与养成、聊天与人设、提醒事项、工作联动、模型与 API、通用与数据。
- 导航、页签和底部操作栏固定，只滚动当前设置；切换页签保留尚未保存的输入。
- 底部按钮调用原有保存逻辑；显示开关、形象切换和自主动作开关即时生效，大小、拖拽、人设、画像、模型设置按对应按钮保存。
- 支持搜索设置名称、方向键切换页签、`/` 聚焦搜索和 `Ctrl+S` 保存当前可保存的配置。搜索不会读取聊天记录、API Key 或个人画像。
- 不迁移或重置个人数据，保留原有 IPC 和后端能力。从源码启动（`npm start`）会重新构建新版面板；已下载的旧便携版不会因更新源码而自动升级，请从 Releases 下载新版完整 ZIP 并解压到新目录使用。

### 桌宠形象与互动

- 内置大肥鱼和白龙，白龙随项目提供 35 段透明 WebM 动画，无需另行下载。
- 在设置面板直接切换大肥鱼／白龙，两种形象均使用程序内置素材，无需配置素材目录或导入。
- **桌宠 → 形象与显示 → 第二只桌宠**：可开启另一只大肥鱼或白龙，支持双鱼、双龙、鱼龙组合；默认不开启。形象与位置按实例区分，大小、动作开关、显示位置、拖拽及反弹参数共享。
- 桌宠大小可在 **100–500 px** 之间调节，默认 400 px；白龙缩小至原来的一半，大肥鱼保持接近原来的大小；补偿素材透明留白后，相同数值下两者可见高度接近。保存后生效，无需重启。
- **桌宠 → 初始位置**：主桌宠和第二只分别保存启动坐标，支持多屏负坐标。先拖到喜欢的位置，点“使用当前位置”，再点“保存并应用位置”；也可直接填写 X/Y。完整重启、切换形象后仍使用保存位置，“恢复默认”返回原来的角落设置。
- 勾选 **“固定在此处”** 后，所选桌宠不会自主走动、奔跑、飞行、被拖走或被碰撞推走；仍可点击、聊天和喂食。该项按桌宠分别设置，原“拖拽设置 → 锁定位置”仍是双宠共享的总开关。屏幕拔掉或布局变化时，会把位置纠正到实际可见屏幕，避免桌宠消失。
- 坐标表示桌宠动画画布左上角的屏幕位置（不是设置窗口位置）；不勾选固定时，仅改变启动／回到初始位置的落点，之后仍可移动。保存与即时应用不重启桌宠进程。
- 支持拖动、右键菜单、隐藏 / 显示、自定义语录与动作表现。
- 可分别控制大幅动作、大肥鱼自由奔跑和白龙自由飞行。大肥鱼在空闲时自动在当前屏幕内跑动，不需要 WASD，也不会打开抢焦点的控制窗口；设置开关即时生效并保存。固定位置、聊天、喂食、拖拽与工作联动时暂停自主奔跑。旧的「控制大肥鱼／扔白饭」入口已移除，右键「喂白饭」保留。
- 关闭设置窗口后继续留在系统托盘；彻底退出请使用托盘菜单或面板中的“退出软件”。

### 拖拽、反弹与隐藏设置

本项目默认显示 **一只桌宠**，也可开启第二只；大小、拖拽、反弹、隐藏与吸边配置共享，切换大肥鱼／白龙不会重置设置。

- **桌宠 → 拖拽设置**：控制拖动物理、静止放手下落、锁定位置和 Shift + 左键拖动；甩出力度可选轻柔、标准、强力或疯狂。修改后点击 **“应用拖拽设置”** 保存并生效。
- **碰撞反弹**控制屏幕边缘与落地，**桌宠之间碰撞**独立控制双宠碰撞（默认关闭）；打开后，自主移动或甩出的桌宠能撞动另一只；按可见身体检测，加入高速扫掠和撞后位置分离，减少穿透与重叠。两者共享撞后弹力、摩擦系数、体重倍率和最大撞击力度，修改后点击“应用拖拽设置”。
- 拖拽物理关闭、锁定位置、隐藏、吸边或正在进行拖拽／菜单／聊天／喂食时，不参与双宠碰撞。
- **桌宠 → 隐藏设置**：独立控制窗口置顶、全屏时自动隐藏、光标隐藏时自动穿透。退出全屏会恢复自动隐藏前的显示状态，不会把手动隐藏的桌宠强制显示。Windows 系统检测不可用时不会持续误隐藏。

### 边缘探头（左右吸边）

1. 在 **桌宠 → 隐藏设置** 开启 **“边缘探头（左右吸边）”**，默认关闭。
2. 按住桌宠拖到屏幕左边或右边，松手后以 **45° 探头**停靠；大肥鱼和白龙都支持。
3. 点击停靠的桌宠会展开，约 **5 秒后自动缩回**；打开菜单、聊天或喂食等互动期间会暂缓缩回。
4. 将桌宠拖回屏幕内部即可解除吸边；关闭开关也会让它立直并回到可见区域。

支持多屏负坐标，相邻显示器之间的接缝不会作为吸边位置。吸边期间不进行自主奔跑、飞行或甩出，避免与停靠姿态冲突。

### 心情与拖动白饭喂食

心情面板显示当前心情、原因及饱腹、亲密等养成状态，并提供心情开关和安静时段设置。

**白饭不会一直放在桌宠旁边，喂食流程如下：**

1. 显示桌宠，并在“大肥鱼现在”中启用心情系统。
2. **右击桌宠 → 选择“喂白饭”**。
3. 屏幕工作区域会随机出现一碗白饭。
4. 按住饭碗，将它拖到桌宠的身体上，再松开鼠标完成喂食。
5. 喂食成功后饭碗消失，桌宠播放吃饭动作并给出反馈；饱腹值增加 **15**（最高 100），亲密度按现有冷却和每日规则增加。

仅点击饭碗或召唤饭碗不会喂食；松在桌宠以外的位置，饭碗会保留，可以继续拖动。**右击饭碗可以取消**。隐藏桌宠或关闭心情系统也会清理当前饭碗。

### 大模型聊天

- 支持对话记录、新建聊天和逐字显示回复。
- 支持设置角色名字、对你的称呼、性格、补充人设与回复动作。
- 可选使用个人画像和补充信息，默认不要求填写。
- 可保存多套第三方 API 配置，设置 API 地址、Key、模型、思考模式、代理与历史轮数等。
- 提供模型列表获取、连接测试与聊天参数配置。
- 关闭“用第三方 API”时，聊天跟随本机 Codex 的配置，包括通过 **CC Switch** 配置的中转服务。

### Codex／DeepSeek Harness 双联动

- 保留 Codex 任务状态感知、窗口联动和“打开 Codex”入口；新增“打开 Harness”，可从管理窗口、托盘或桌宠右键菜单启动 Harness，并恢复最小化／托盘隐藏的窗口、切到前台；不会只启动后台进程。
- 管理窗口的 **工作联动** 中，Codex 与 Harness 可独立开关，默认同时开启；不受聊天模型选择影响。
- Harness 通过本机零依赖插件发送工作元数据：思考、工具执行、整理回复、等待审批／回答、完成、错误和空闲。桌宠复用现有动作、气泡与心情反馈。
- 等待你操作的任务优先显示。一边完成、另一边仍在工作时，不会播放“全部完成”的反馈；Harness 自动目标续跑的中间轮也不会被当成整个目标完成。
- **状态感知本身不调用模型、不消耗 API 额度。** Codex 公开进展仅在本机气泡显示，不上传、不写入桌宠聊天上下文。Harness 本地桥接只输出状态、泛化任务标签、会话 ID 和时间等元数据。若另行启用聊天“让她知道此刻的状态”，泛化工作状态可随主动聊天发送给所选模型。
- **不再查询或显示 Codex 账号额度**。使用第三方 API 聊天时，不要求 Codex 账号；只启用状态感知时也不需要 API Key。

#### Codex 实时气泡联动

开启“感知 Codex 工作状态”后，桌宠直接在原有气泡显示正在运行任务的公开进展和结果，不需要手动选择项目。

- Codex 仍在执行任务、没有新的公开进展可显示时，持续显示“撰写回复中”；首条公开进展到达后立即替换。
- 普通进展最多每 10 秒合并更新，每条只显示一次、约 10 秒后结束展示；任务仍在运行则恢复“撰写回复中”，直到新进展或状态变化。气泡只显示正文，不加 Codex／项目名／进展标题。
- 本轮完成、失败、中断和需要确认时立即静音提示；并发任务的结果不会被另一个任务的进行中状态覆盖。结果约 15 秒后收起，完整内容回 Codex 查看。
- 不设项目列表、详情页、历史记录或未读角标。只在内存保留当前进展和短暂去重状态，退出即清空；不回放启动前已结束的任务。
- 只读本机 Codex 已公开的任务消息，不读取私有推理或工具输出，不启动模型任务，不查额度。不跟随子代理、自动化任务或桌宠聊天沙盒。
- 数据库暂不可用、遗留任务没有新状态时，绝不推断为完成。“本轮完成”也不代表整个项目全部完成。

旧版本生成的 `codex-project-reports.json` 不再读写；已有文件保留，不影响联动。

#### 首次接入 Harness

1. 安装并正常打开过 DeepSeek Harness。默认 Profile 为 Windows 用户目录下的 `.dsh/profiles/desktop`。
2. 打开桌宠管理窗口 → **工作联动 → Harness 桥接与启动设置**。
3. 如使用其他 Profile，先点击“选择 Harness Profile”；再点击 **安装／更新本地桥接**。
4. **完全退出并重新打开 Harness**（仅关闭窗口可能仍留在托盘），再开始一条任务。连接状态应显示“已连接”。
5. 点击 **打开 Harness**：默认使用 `dsh` 协议注册的本机 EXE；未注册协议或安装在其他位置时，点击“选择 Harness 软件”指定 EXE。启动时隔离桌宠的数据目录环境变量，保留 Harness 原有的登录配置，并等待窗口恢复、显示到前台；不是另开一个网页或要求重新填写 API Key。

安装保留已有依赖、插件和模型设置，只添加 `@codex-dafeiyu/harness-bridge` 本地包。已有旧版 dsh-pet 桥接不会被覆盖；不支持的 Profile／锁文件格式会明确拒绝，不会强行修改。

联动设置保存在个人数据目录的 `integrations.json`。桥接代码位于 `%APPDATA%/CodexPet/harness-bridge`，配置清单、锁文件及更新前桥接代码备份位于 `%APPDATA%/CodexPet/harness-bridge-backups/<时间戳>`。安装失败会自动回滚；需要手动撤销时，先退出 Harness，参照备份的 `restore-info.json` 恢复原 Profile 清单和锁文件，仅移除该记录标明新建的插件链接；如有 `bridge/` 备份，恢复其中旧桥接代码。

桥接心跳超过约 15 秒或宿主进程退出时，状态回到未知／空闲，不误报成功。启动桌宠时只恢复当前活跃任务，不重播历史完成反馈。正在运行的 Harness 必须重启才能加载新插件；插件不回放安装前的会话事件。

#### 状态与使用边界

| 状态 | 桌宠反馈 |
| --- | --- |
| 思考／执行工具／整理回复 | 显示正在处理的来源和泛化任务提示 |
| 等待审批或回答 | 优先提示你处理，不视为任务已完成 |
| 本轮完成／出错 | 显示对应反馈；另一边仍工作时不提示全部完成 |
| 未连接／心跳失效 | 提示检查桥接，失效的工作状态不会继续保留 |

- **“感知 Harness 状态”不等于“用 Harness 聊天”**：桌宠聊天仍按“聊天用的大模型”设置，跟随 Codex／CC Switch 或使用独立第三方 API。
- 选择 Harness Profile 只决定桥接安装位置，不会把 EXE 启动切换到另一套账号或 Profile。
- 桥接文件只在本机 `%APPDATA%/dsh-pet-bridge` 中交换；不提供跨设备远程控制，也不会上传 Harness 的聊天正文。

### 提醒事项

- **DDL 小便签**：整理提醒、确认后保存，支持一次性、每天或每周重复，以及提前提醒；提醒保存在本机。
- 软件退出或关机时不会弹出提醒，重新打开后会补提醒，不能替代系统级闹钟。

完整便携版已包含 Electron、Node.js、运行依赖、大肥鱼与白龙素材和 Harness 桥接插件，不需要另装 Node.js、npm 或 Git。要求 **Windows x64**；请保留同目录的 DLL、`resources`、`locales` 等运行文件。

- 可选校验：从发布页下载同名 `.zip.sha256` 文件，在 PowerShell 执行 `Get-FileHash .\Codex-dafeiyu-v1.7.0-windows-x64.zip -Algorithm SHA256`，将结果与校验文件中的值比较。

### 方式二：从源码运行（开发者）

#### 1. 准备环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows x64；当前启动 / 打包脚本不支持 macOS、Linux 或 Windows ARM64 |
| Node.js | **24.19.0**，与 `.nvmrc` 一致；当前脚本严格检查版本 |

可从 [Node.js 官网](https://nodejs.org/) 获取对应版本，安装后重新打开 PowerShell，检查：

```powershell
node --version
npm --version
```

`node --version` 应输出 `v24.19.0`。不要使用其他 Node 版本直接跳过检查。

#### 2. 下载仓库

```powershell
git clone https://github.com/wanhkjd/MyCodexDafeiyu.git
cd MyCodexDafeiyu
```

如果下载的是源码 ZIP，请解压后，在包含 `package.json` 的目录打开 PowerShell。

#### 3. 安装依赖

```powershell
npm ci
```

请保留 `package-lock.json`。首次安装会下载锁定版本的 Electron，可能需要等待一段时间。

#### 4. 启动桌宠

```powershell
npm start
```

启动脚本会先构建本地运行目录，再打开桌宠。**第一次运行基础桌宠功能不需要填写 API Key**；使用聊天等模型功能时，再按照下一节配置。

## 首次配置大模型

打开设置面板中的 **“聊天用的大模型” → “设置”**，选择以下一种方式。

### 跟随本机 Codex / CC Switch

1. 先确认本机 Codex 可以正常请求你选择的模型服务。
2. 如果使用 CC Switch，请先在 CC Switch 中完成 Codex 对应的服务商、中转地址和密钥配置。
3. 在桌宠中保持 **“用第三方 API”关闭**。
4. 发送一条消息检查是否能够回复。

桌宠跟随的是本机已有配置，并不会替你安装 Codex、配置 CC Switch 或创建服务商账号。没有本机 Codex 环境时，可改用下方独立 API 方式。

### 单独配置第三方 API

1. 打开 **“用第三方 API”**，选择或新增一套配置。
2. 选择服务商，填写对应的 **API 地址、API Key 和模型名**；实际支持范围以服务商预设和接口兼容性为准。
3. 如有需要，设置系统代理、直连或指定代理地址。
4. 点击 **“测试连接”**，确认成功后点击 **“保存”**。

> 连接测试会发送一条短消息，可能产生少量 API 费用。关闭 Codex 账号额度查询并不代表模型调用免费，计费规则由实际服务商决定。请勿把 API Key、Cookie 或账号凭据提交到仓库。

## 构建与打包

在源码目录安装依赖后，可以执行：

| 命令 | 用途 |
| --- | --- |
| `npm start` | 构建本地运行目录并启动桌宠 |

当前 v1.7.0 的默认输出位置：

版本号变化时，输出名称会相应变化。构建会重新生成对应的输出目录，不要在生成目录中保存唯一一份自定义文件。**发布素材前，请先确认下方所列授权边界。**

### 更新正在使用的便携目录

源码或 `dist` 更新不会自动修改另一个便携目录。目录名称也可能保留旧版本号，应以正在运行的 EXE 所在目录为准。对本仓库内指定的便携目录，可执行：

```powershell
.\scripts\update-local.ps1 -PortableDirectory 'D:\Ai\Codex-dafeiyu\Codex-dafeiyu-v1.6.0-windows-x64' -CloseRunning -NoBackup
```

上面的命令不产生备份，仅同步程序文件并逐文件校验，不会迁移或重置个人数据。省略 `-NoBackup` 时才会备份被替换文件。完成后重新打开该目录的 EXE。跨版本更新推荐完整解压新版 Releases ZIP 到新目录，再从托盘彻底退出旧版后启动新版。

## 常见问题

**开启吸边后没有看到探头？**

开关不会把当前桌宠自动移到边缘。需拖到屏幕最左／最右外侧边缘后松手；相邻显示器接缝不吸附。若开启了“锁定位置”，先关闭；若开启“Shift + 左键拖动”，拖拽时需按住 Shift。旧版本没有此功能，请正常退出旧实例后启动 v1.7.0（该功能自 v1.6.0 起提供）。

**升级会丢失聊天记录和设置吗？**

个人数据仍使用当前 Windows 用户的 `%APPDATA%\CodexPet`，不会包含在发布包内。请先从托盘彻底退出旧版，再把新版完整解压到新目录启动；不要同时运行两个版本，也不要用新版包覆盖个人数据目录。

**安装时报 Node 版本不符 / `EBADENGINE`？**

检查 `node --version` 是否为 `v24.19.0`，以及 npm 是否为 11 或以上。安装对应版本后重新打开终端，再执行 `npm ci`。

**PowerShell 提示无法加载 `npm.ps1`？**

可以使用 `npm.cmd ci`、`npm.cmd start` 或 `npm.cmd run package:win` 执行同样的命令，无需为此全局降低脚本执行策略。

**Electron 下载失败或安装很慢？**

检查网络、代理和 npm / Electron 下载访问情况，再重试 `npm ci`。不要手动替换为其他版本的 Electron 来绕过构建校验。

**聊天没有回复？**

先确认当前使用的是本机 Codex 还是独立第三方 API，再检查对应配置、模型名、Key、服务商权限和代理。跟随 Codex 时，先检查 Codex 本身能否正常请求；独立 API 时，使用“测试连接”。

**本机 Harness 已登录，桌宠打开时还提示登录或 API Key？**

先确认“启动”显示的是你日常使用的 Harness EXE，必要时重新选择。v1.5.0 起，启动时会清除桌宠私有的 `DSH_HOME`、Electron 与 Node 环境变量，避免让 Harness 使用桌宠的数据目录；不复制、重置或修改账号凭据。若从旧版升级，请先正常退出错误启动的 Harness 实例，再打开日常使用的本机 Harness。

**点击“打开 Harness”只看到后台进程，窗口没出现？**

v1.5.0 起会等待实际窗口出现，恢复最小化／托盘隐藏的窗口并激活到前台；没有成功显示时会报错，而不是仅因进程启动就提示成功。首次启动或弹出登录／更新／确认窗口时可能需要等待；如仍失败，检查 EXE 路径，并确认桌宠和 Harness 使用相同权限运行，优先都用普通用户权限。前台激活仅支持 Windows，依赖系统自带的 Windows PowerShell；不会修改系统执行策略，也不会把窗口设为永久置顶。

**Harness 已打开，但状态仍显示未连接？**

确认桥接安装到了实际使用的 Profile，且“感知 Harness 工作状态”已启用。安装后需完全退出并重启 Harness，仅关闭窗口可能仍留在托盘。可展开“Harness 桥接与启动设置”检查安装状态；“已安装”表示文件已安装，不代表正在加载。插件不回放安装前的会话事件，请在重启后开始新一轮任务。

**右键没有白饭或无法喂食？**

确认桌宠可见、心情系统已启用。选择“喂白饭”后需要实际拖动饭碗，并在桌宠身体上松手；点击饭碗或松在窗口透明边缘不会喂食。

**换电脑后配置或 Key 不见了？**

个人数据不在仓库中，不会随 `git clone` 下载；系统加密的凭据也不能保证跨机器直接使用，请在新电脑重新配置。
